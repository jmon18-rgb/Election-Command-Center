# Integrity source review and visible limits

The installed editorial tools apply an independently accepted source-review decision without replacing a newer queue. The page shows source-specific evidence and limits on a source-checked card. The three tools and native source disclosure are integrated in source; reviewed data decisions are applied separately through an accepted keyed delta. Source integration is not publication, legal validation or incident admission.

`data/integrity_review_queue.json` remains the canonical manual-review source. The existing `scripts/update_integrity_queue.py` preserves prior item decisions and owns pending/checked counts and advisory headline grouping. The local Node applier reads the latest queue, checks each exact lead ID and the SHA256 of its `JSON.stringify` preimage, and rejects changed or missing records rather than overwriting them. Only `review_status`, `primary_sources`, `review_notes` and `reviewed_as_of` may change. Numeric impact verification and incident promotion must stay false/null. Every other latest item and metadata field, including the feed clock and `new_leads`, survives. Counts and advisory groups are recomputed by calling the installed pure Python `triage(items)` function, not a second policy or the collector's `main()`.

The default command checks and reports without writing:

```text
node scripts/apply_integrity_queue_review.cjs --delta /absolute/path/reviewed-delta.json
```

After independent source review is actually accepted, `--apply` also requires `INTEGRITY_QUEUE_REVIEW_APPLY_AUTHORIZED=INDEPENDENT_SOURCE_REVIEW_ACCEPTED`. It rechecks that the queue file has not changed during preparation, then replaces it through an exclusive temporary file in the same directory. An already-applied or subsequently changed lead fails its preimage check. Apply the keyed delta to the latest queue; do not promote a prepared whole-queue snapshot.

Linux uses `python3`. On a host where Python is not on that path, set `INTEGRITY_REVIEW_PYTHON` to the existing Python executable. The applier pins the triage source hash declared by the reviewed delta and disables bytecode writes for its subprocess. This is an editorial application guard, not a sandbox, independent fact checker or source-authentication service.

The retained Alaska source-review example refers to one case, `3:26-cv-00376-SLG`, and two existing news leads. The retained Document 64 text supports an October 30 order expediting consideration and setting stated response/reply deadlines. It does not grant dismissal, block certification, establish voter confusion or quantify voter impact. The retained Document 43 passage describes requested certification-related relief; a request is not an operative remedy. No broader theory or June 26 claim is copied into these decisions.

These are copies of filed documents hosted by Democracy Docket, reviewed through extracted text. They are not authenticated official-court-host captures. The direct Document 64 PDF request returned 403 and stopped; original PDF bytes and hashes are absent. Other original PDF captures were not attempted after that stop. The disclosure makes this distinction visible alongside the checked date, case number, source attribution, validated HTTPS links, review notes and source-specific limits.

The existing cards gain a native `details`/`summary` disclosure labelled “Reviewed sources and limits”. Text uses the existing `elt()`/`textContent` helper; reviewed links require absolute HTTPS with no credentials or control/space characters. Pending cards, the twelve-card bound, raw article links, empty-state wording and summary semantics remain. No new IDs, custom keyboard handler, source request or global text block is added. DOM checks establish focusable native summaries and normal activation, not a physical-browser keyboard or geometry result. Those belong to the normal integration gates.

There is no change to `data/integrity_impact.json`, monitoring scores, probabilities, voter counts, forecasts, source eligibility or call admission. In particular, the current monitoring function assigns four points to any curated `legal_dispute`; this editorial workflow adds no such row. No native Alaska ballot, candidate, party, RCV or results contract is admitted.

The installed tools are scripts/apply_integrity_queue_review.cjs, scripts/test_integrity_queue_review.cjs and scripts/test_integrity_review_disclosure.cjs. The existing Python producer is unchanged and is used through its pure triage function. The page receives only the reviewed renderer change; full candidate HTML, old queue snapshots, local logs and preparation files are not application inputs. A source-specific keyed delta requires separate independent review and root acceptance before application. The mechanics test is self-contained and uses fabricated editorial examples, not an admitted election or court dataset. It requires existing Python. The extracted renderer test reads the actual repository index and uses the existing JSDOM dependency from the full DOM check environment; it does not establish physical-browser keyboard or geometry results. Normal browser, CI and publication gates remain separate. No source retrieval, producer refresh or model run is needed for these two focused checks.
